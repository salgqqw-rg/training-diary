# Solo. — дневник тренировок

Next.js 15 (App Router) + Supabase. Циклы по неделям, подходы с RIR и RPE, прогресс по упражнениям,
питание и сон, замеры, цели, связь «тренер — подопечный» и чат.

## Что есть

- **Главная** — ближайшая и последние тренировки, вес, объём за 30 дней.
- **Дневник** — циклы (программы по неделям). В цикле: тренировки по неделям, упражнения, таблица подходов.
  Подходы можно вводить строкой: `80x8, 82,5x6 @2` (вес × повторы, `@` — RIR).
  Над подходами видно, что было «в прошлый раз». Тренировку можно **скопировать** в любую неделю и дату.
  Кнопка **«⏱ Отдых»** — таймер между подходами (запускается сам по «+ подход», в конце вибрация и сигнал).
  Кнопка «Сохранить подходы» фиксирует их — потом строки не редактируются.
- **Упражнения** — каталог с фото и описаниями + свои упражнения, рекорды.
- **Прогресс** — вкладка «Упражнения»: график веса, расчётного 1RM или объёма по выбранному упражнению;
  вкладка «Обзор»: объём по неделям, новые рекорды, группы мышц, активность по дням недели.
- **Питание и сон** — дневник питания (поиск продуктов), сон, шаги, БЖУ, добавки; график динамики.
- **Характеристики** — замеры тела и фото формы; график динамики по любому показателю.
- **Цели**, **Подопечные** и **Сообщения** (тренер ↔ подопечный), **Лента** публичных циклов.
- **Профиль** — имя, фото, email, пароль, удаление аккаунта, **экспорт данных в CSV** (тренировки, замеры, питание и сон).
- Сайт устанавливается на телефон как приложение (манифест + иконки).

## Запуск с нуля

1. Создайте проект на [supabase.com](https://supabase.com).
2. В SQL Editor выполните `supabase/schema.sql` — он уже включает всё до `migration_14` включительно.
3. Затем по порядку выполните `migration_15` … `migration_23` из папки `supabase/`
   (каталог продуктов, план питания, библиотека упражнений, индексы, заметки, блокировка подходов, время отдыха и тренировки).
4. Authentication → Providers → Email: для разработки отключите «Confirm email».
   Для входа через Google включите провайдер Google.
5. Authentication → URL Configuration → Redirect URLs добавьте адреса сайта:
   `http://localhost:3000/**` и `https://<ваш-домен>/**`.
6. Скопируйте `.env.example` в `.env.local` и заполните (см. ниже).
7. Установите зависимости и запустите:

   ```
   npm install
   npm run dev
   ```

   На Windows можно запускать `start-dev.bat`. Сайт: http://localhost:3000

### Уже есть база

Выполните недостающие миграции по порядку. Все они безопасны к повторному запуску, кроме `migration_13`

## Переменные окружения

| Переменная | Нужна | Зачем |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | да | адрес проекта Supabase |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | да | публичный ключ (Project Settings → API) |
| `SUPABASE_SERVICE_ROLE_KEY` | для удаления аккаунта | только сервер, в браузер не попадает. Без него удаление выдаёт понятную ошибку, остальное работает |
| `NEXT_PUBLIC_SITE_URL` | если сайт за прокси | адрес для писем сброса пароля и входа через Google |
| `FATSECRET_CLIENT_ID`, `FATSECRET_CLIENT_SECRET` | нет | дополнительный (англоязычный) источник продуктов |

## Каталог продуктов

Поиск продуктов идёт по продуктам пользователей, по каталогу Open Food Facts в вашей базе и (необязательно) по FatSecret.
Загрузить каталог (Россия, Беларусь, Казахстан): сначала `migration_15`, затем `import-food.bat`
(или `node scripts/import-openfoodfacts.mjs`). Первый запуск — «пробный», ничего не пишет.

## Тренер — подопечный

1. Тренер на странице «Подопечные» отправляет заявку по email подопечного (учётка должна существовать).
2. Подопечный принимает заявку на той же странице — связь активна.
3. Тренер видит циклы, замеры, питание, цели подопечного в режиме просмотра, может составить для него цикл.
4. Права заданы в базе через Row Level Security: тренер получает доступ только к подопечным с активной связью.
5. Разорвать связь может любая из сторон.

## Безопасность

- Права на данные задаёт база (RLS): пользователь видит и меняет только своё, публичные циклы видны всем,
  тренер — данные своих подопечных.
- Подлинность сессии на сервере проверяет `getUser()` (`src/lib/auth.ts`), а не просто кука.
- Пароль — от 8 символов. Перенаправления после входа ограничены путями внутри сайта (`src/lib/safe-next.ts`).
- Значения подходов (вес, повторы, RIR, RPE, отдых) ограничиваются на сервере (`src/lib/sets.ts`).
- Файл `.env.local` в git не попадает; хранится только шаблон `.env.example`.

## Часовой пояс

«Сегодня» считается по часовому поясу браузера: он запоминается в куке `tz` (`src/components/tz-sync.tsx`),
сервер читает её в `src/lib/today.ts`. Без куки — UTC.

## Разработка

```
npm run typecheck   # проверка типов
npm test            # тесты чистой логики (нужен Node 22.6+)
npm run check       # и то и другое
```

Тесты лежат в `tests/` и покрывают модули без зависимостей от фреймворка: разбор подходов, даты,
аналитика, CSV, группы мышц, постраничное чтение, «в прошлый раз».

Структура: `src/app` — страницы, `src/lib` — действия сервера и логика, `src/components` — общие компоненты,
`supabase/` — SQL-схема и миграции, `scripts/` — импорт каталога продуктов.
