# Дневник тренировок

Next.js + Supabase. Регистрация, личный кабинет, циклы по неделям, подходы с RIR и RPE, публичная лента, связь «тренер — подопечный» и статистика прогрессии.

## Запуск (с нуля)

1. Создайте проект на supabase.com.
2. В SQL Editor выполните файл `supabase/schema.sql`.
3. В Authentication → Providers → Email для разработки отключите "Confirm email", чтобы вход работал сразу после регистрации.
4. Скопируйте `.env.example` в `.env.local` и вставьте URL проекта и anon key (Project Settings → API).
5. Установите зависимости и запустите:

   npm install
   npm run dev

6. Откройте http://localhost:3000

## Уже есть база? Выполните миграцию

Миграция добавляет связь «тренер — подопечный»: таблицу `coach_links`, email в профиле, заявки на связь и доступ тренера к циклам подопечных. В SQL Editor Supabase выполните один раз `supabase/migration_01_coach_links.sql`.

## Как работает связь «тренер — подопечный»

1. Тренер на странице «Подопечные» отправляет заявку по email подопечного (учётка должна быть зарегистрирована).
2. Подопечный на той же странице принимает заявку — связь становится активной.
3. Теперь тренер на странице «Подопечные» видит всех подопечных, их циклы и может открыть любой цикл в режиме просмотра: все тренировки, подходы, веса и статистика прогрессии, но без права менять данные.
4. Права заданы в базе через RLS: тренер получает доступ только на чтение и только к подопечным с активной связью. Изменить данные подопечного нельзя даже через вызовы API из браузера.
5. Разорвать связь может любая из сторон.

## Профиль

Страница «Профиль»: смена имени, фото (Storage-бакет `avatars`, до 5 МБ), email (с подтверждением письмом), пароля и полное удаление аккаунта (циклы, замеры, фото, связи с тренерами учётка в Supabase Auth). Для аватаров в Supabase нужно применить миграции `supabase/migration_02_profile.sql` и `supabase/migration_03_measurements.sql`.

**Удаление аккаунта** требует ключа `SUPABASE_SERVICE_ROLE_KEY` в `.env.local` — возьмите его в Project Settings → API → service_role. Он работает только на сервере и не попадает в браузер. Без ключа удаление выдаёт понятную ошибку, остальной сайт работает.

## Характеристики

Страница «Характеристики»: замеры объёмов и веса по месяцам (бицепс левый/правый, плечи, грудь, бедро левое/правое, талия, икра левая/правая, вес, рост) + фото формы за любой месяц. Тренер видит замеры и фото своих активных подопечных (ссылка «Замеры» в кабинете на «Подопечных»). Перепишете замеры за тот же месяц — запись обновится.

## Питание и сон

Страница «Питание и сон»: запись за каждый день — сон (ч), шаги, калории, БЖУ (белки/жиры/углеводы) и заметка. Повторное заполнение той же даты обновляет запись. Тренер видит дневник своих подопечных (ссылка «Питание и сон» в кабинете). Миграция: `supabase/migration_04_daily_logs.sql`.

## Деплой

Подключите репозиторий к Vercel и добавьте те же две переменные окружения.

## Безопасность

Права доступа заданы в базе через Row Level Security. Пользователь видит и меняет только свои циклы, публичные циклы видны всем, подтверждённый тренер видит циклы своих подопечных. Проверка на сервере не даёт обойти эти правила из браузера.
